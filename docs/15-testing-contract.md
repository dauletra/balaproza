# 15 · Тестовый контракт

> ⚠️ **Документ отстаёт от суиты и будет удалён на шаге 3 плана оптимизации.**
> Шаг 2 сливает 25 тест-файлов в 13 и убирает около девятисот тест-методов;
> таблицы ниже перечисляют файлы, которых уже нет. Правдивый источник —
> сам каталог `core/tests/`. См. [`PLAN-OPTIMIZATION.md`](../PLAN-OPTIMIZATION.md) §2.6.

> `Обновлён: 2026-08-26` · `Сверен с кодом: 6b01a3a`

1047 тестов в 20 файлах — это не «покрытие», а **исполняемая часть ТЗ**. [12 §12.6](12-domain-model-contract.md) прямо на это опирается: «existing tests are the behavior contract». Пока контент живёт на стабе, тесты — единственное, что не даёт вёрстке разъехаться молча.

Этот документ описывает, что защищает каждый файл и что считать регрессией. Он нужен по двум причинам: часть тестов кодирует архитектурные решения, которых нет ни в одном DEC (§15.4), и при Ф14 эти же тесты станут приёмочным критерием миграции на модели.

```bash
uv run python manage.py test core
```

```bash
uv run python manage.py test core.tests.test_catalog
```

## 15.1 Принципы

Они выведены из самих тестов, а не назначены задним числом.

1. **Проверяем текстовые маркеры, не DOM-классы.** Из `test_home`: «не утверждаем DOM-классы (хрупко), только наличие текстовых маркеров, которые специфичны для каждого режима». Тест на `class="flex gap-3.5"` ломается при любом рефакторинге вёрстки и ничего не значит; тест на наличие строки «Аптаның кітабы» значит, что блок отрендерился.

2. **Исключение — когда проверяется именно раскладка.** `test_desktop_layout` намеренно читает классы: там предмет проверки и есть брейкпоинт (§15.4).

3. **Оба режима, всегда.** Гость и авторизованный — разные ветки почти на каждой странице. Тесты идут парами: `LibraryGuest` / `LibraryAuthed`, `MyStoriesGuest` / `MyStoriesAuthedHasItems`, `ContestSubmitGuest` / `ContestSubmitForm`.

4. **Пустое состояние — отдельный класс.** `MyStoriesAuthedEmpty`, `LibraryEmpty`, `NotificationsEmpty`, `MySubmissionsEmpty`, `ManageStoryEmptyChapters`. Пустое состояние обязательно по DEC-17 и ломается чаще, чем заполненное.

5. **Неизвестный slug — отдельный класс.** `GenreDetailUnknown`, `CollectionDetailUnknown`, `TagDetailUnknown`, `StoryDetailUnknownSlug`, `ManageStoryUnknown`, `ContestDetailUnknown`, `ProfileOtherUnknown`. Страница обязана деградировать, а не падать 500.

6. **Логин в тестах — один помощник на всю суиту**, `core/tests/base.py`:

```python
login_as(client)                        # aidana — корпус, все статусы работ
login_as(client, 'bekzhan_t')           # другой автор корпуса
login_as_newcomer(client, 'lonely_reader')   # вошедший, у которого ничего нет
```

Раньше сниппет с тремя ключами сессии повторялся в четырёх файлах и ещё десяток раз писался по месту. С настоящим входом (этап 9) подделывать сессию нельзя и не нужно: `login_as` делает `force_login` под пользователем корпуса.

У `aidana` есть произведения с разными статусами — на них смотрят авторский кабинет, профиль и библиотека. Пустые состояния берут `login_as_newcomer`: он **заводит** пользователя, потому что «Сақталғандар жоқ» показывают аккаунту без библиотеки, а не отсутствию записи о нём.

7. **Корпус в тестовой базе — один раз за прогон.** С Ф14 страницы читают базу, и почти каждому тесту нужны данные. Их кладёт `core/tests/runner.py` сразу после миграций; дальше работает обычный откат транзакции, поэтому корпус видят все тесты и никто не переносит чужих изменений. Сеять в `setUpTestData` было первым решением и стоило трёх минут на суиту вместо минуты — двести тест-классов, двести прогонов сида.

   Цена: пустой таблицы тест больше не получит. Тесты, которым нужны свои объекты, заводят их под своими именами — слаги и ники демо-корпуса заняты.

### `test_urls_smoke.py` — самая дешёвая защита

Пять тестов, но покрывают все маршруты: списки `PUBLIC_URLS` (28 записей) и `DEBUG_ONLY_URLS` прогоняются через `subTest`. Ловит целый класс ошибок дизайн-фазы:

- сломанные `{% url %}` после переименования маршрута;
- отсутствующий партиал в `{% include %}`;
- запрещённые имена переменных (Django блокирует начинающиеся с `_`);
- зацикленный include;
- падающий кастомный фильтр или тег.

**Добавил маршрут — добавь строку в `PUBLIC_URLS`.** Иначе он не покрыт ничем.

`DebugOnlyEnforcement` отдельно проверяет, что `/_design/*` при `DEBUG=False` недоступны: showcase-страницы не должны утечь в прод.

### `test_corpus.py` — инварианты данных

Инварианты демо-содержимого: сумма реакций сходится с числами в списке глав (BR-14a), объявленное «17 бөлім» не расходится с написанным текстом, в редакционной подборке не лежит черновик, знаки автора выводятся из его работ (BR-ACH-01). Ломаются они не от правки кода, а от правки данных.

**Добавил произведение или подборку — эти тесты поймают опечатку.** До Ф14 они проверяли литералы стаба; теперь — базу, куда те же данные кладёт сид. Восемь проверок при переезде ушли: они сторожили то, за чем следит схема (найдётся ли автор произведения, не больше ли двух жанров).

### `test_catalog.py` — самый крупный файл раздела

Помимо базового поиска и жанров держит три вещи, введённые DEC-26/DEC-27:

- `CatalogFilterCombination` — комбинации через query-string (`/genres/triller/?tag=mektep`) действительно сужают выборку, а не игнорируются;
- `CatalogFilterHelper` — валидация по белому списку: неизвестное значение параметра игнорируется, а не роняет страницу;
- `TagDetailPendingBlocked` — pending-тег не даёт публичную страницу (BR-TAG-07).

`GenreDetailKnown` / `CollectionsList` проверяют, что старые canonical URL после унификации движка рендерят те же маркеры — это и был критерий приёмки DEC-27.

Четыре класса закрывают FR-CAT-08 и мобильную раскладку каталога — все они про регрессии, которые видно только на телефоне и которые не роняют ни одной страницы:

- `CatalogStateIsCarried` — ссылка жанра или тега несёт остальные оси и не сбрасывает их молча; явный `sort` едет с ней, неявный — нет (иначе `popularity` каталога отменяла бы DEC-31 на странице тега);
- `CatalogSecondAxisFromQuery` — `?tag=` и `?genre=` действительно читаются движком, путь сильнее query, неизвестная и pending-ось игнорируются;
- `CatalogActiveChips` — каждая включённая ось получает чип, и чип снимает только свою ось;
- `CatalogMobileControls` / `BookCardWideOnMobile` — панель управления липкая, сортировка доступна вне модалки, лист не автосабмитит (`$el.requestSubmit()` ровно один раз на страницу — в рейле), у карточки есть мобильный брейкпоинт.

Пять классов держат DEC-36 — переориентацию каталога с атрибутов на вопрос читателя:

- `TrendingIsTheDefaultSort` — каталог открывается окном в 14 дней, порядок **не совпадает** с накопленным `views` (если совпал — ось ничего не добавляет и стаб врёт), `popularity` остаётся доступной, тег по-прежнему на `recent`;
- `QualityBadgeAxis` — «Редакция таңдауы» и «Байқауға қатысады» отбираются как ось, неизвестный ключ игнорируется;
- `CatalogPresets` — счётчики пресетов сверяются с реальной длиной выдачи по их же ссылке, пустые пресеты не показываются, активный снимается повторным тапом и поглощает чипы своих осей;
- `DraftsAndModerationStayOutOfTheCatalog` — DEC-23 в выдаче: «Модерацияда» не видна ни в каталоге, ни в поиске;
- `EmptyCatalogOffersAWayOut` — пустой экран предлагает жинақтар, а не только «поменяй сүзгі».

Ещё два — про сами оси сүзгі:

- `ReadingTimeBuckets` — проверяет **функцию границ** (`length_bucket` на 10/11 и 30/31) и то, что подписи называют те же числа. Наполнение бакетов не проверяется сознательно: «во всех трёх что-то есть» снова привязало бы пороги к текущему стабу, и сборка падала бы, когда длинные работы уйдут в архив, хотя дизайн исправен;
- `NewAuthorsAxis` — ось «Автор» отбирает по числу подписчиков, исключает известных, комбинируется с жанром и предлагается пресетом.
- `AudienceIsCumulative` — старшая вилка включает младшую, а младшая **по-прежнему не показывает старшие отметки**: это единственная гарантия оси, и её проверка важнее остальных в классе.
- `KindReplacesFormatAndStatus` — три значения «Түрі» делят каталог без пересечений и без остатка, «Формат» и «Мәртебесі» из панели ушли, legacy-параметры продолжают фильтровать;
- `SerialCompletionIsAlwaysKnown` — **правило BR-10a**: у публичного сериала не бывает статуса `Published`, у одночастевого не бывает меток завершённости. Это тот инвариант, ради которого DEC-37 и принимался;
- `PublicStatusesAreNotSpelledOut` — сериалы на месте в рядах главной и в индексе Cmd+K. Литерал `'Published'` вместо `PUBLIC_STATUSES` — тихая пропажа: страница отдаёт 200, просто без десяти произведений, и заметить это без теста негде.

### `test_story.py` — контракт инлайн-чтения

Docstring перечисляет предмет прямо: валидный/невалидный slug, чтение главы через `?chapter=N`, тизер для первой главы, prev/next в граничных случаях, комментарии к главе, gate для гостя, report-модал только авторизованному, прогресс чтения только при совпадении slug.

`StoryDetailSingleWork` держит DEC-28: у `format=single` нет оглавления и prev/next.

### `test_contests.py` — бизнес-правила, а не вёрстка

Единственный раздел, где тесты проверяют настоящие правила: `ChecklistHelpers` (BR-22 — пять критериев), `SubmissionCandidates` (BR-24 — форма сообщает, а не отклоняет), `ContestSubmitAlreadyDone` (BR-23 — одна работа на конкурс), `ContestSubmitForm` (DEC-21 AI-декларация, DEC-24 подтверждение возраста).

При Ф14 эти тесты переезжают на модели **без изменения смысла** — они описывают правила, а не стабы.

Отдельный класс — тесты на **хранимое производное**: `ContestDatesAreTheSource` (фаза и отсчёт считаются от дат), `SubmissionDatesAreReal` (подача лежит внутри окна приёма, а не описана строкой), `NotificationTime` (время и группа уведомления выводятся из `days_ago`). Все три проверяют отсутствие поля, а не его значение: пока поле есть, оно рано или поздно разойдётся с данными, и никакое сравнение значений этого не поймает.

## 15.4 Два файла, которые являются архитектурными решениями

Эти тесты не проверяют требование из ТЗ — они **сами и есть** решение, зафиксированное исполняемо. Оба появились после того, как соответствующая ошибка уже случилась в проде вёрстки.

### `test_template_lint.py` — то, что молча не работает

Общий знаменатель этих тестов: ошибка не падает, не пишет в консоль и не видна при ревью — заметить её можно только на живом сайте, а часть — вообще только скринридером.

- `TemplateCommentSyntax` — `{# … #}` обязан быть однострочным. Django парсит его как single-line; многострочный комментарий выводится на страницу как текст. Именно это случилось с `search_popup.html` и утекло в footer **всех** страниц сразу.
- `TemplateTagSyntax` — `{% … %}` тоже не переживает перенос строки. Отсюда правило «`{% include … with … %}` всегда в одну строку», даже если строка получается длинной.
- `AlpineDirectivesAreInScope` — `@click` / `@submit` / `x-*` вне поддерева с `x-data`. Alpine 3 инициализирует только найденные по `x-data` корни, поэтому такая директива остаётся мёртвым атрибутом: кнопка выглядит и нажимается как кнопка и не делает ничего. На момент введения теста так не работали 19 интерактивов на 13 страницах — кнопка сүзгі каталога, «Іздеу ашу» на 404, обе кнопки удаления произведения и семь форм с `@submit.prevent`, которые вместо демо-тоста уходили настоящим POST. Проверка идёт по **отрендеренному** HTML: предок с `x-data` часто лежит за `{% include %}` в другом файле, и статикой это не разобрать.

- `IconIncludesAreIsolated` — `components/icon.html` подключается только с `only`. `{% include … with … %}` наследует весь родительский контекст, и `label` кнопки, бейджа или пилюли молча доезжал до иконки: та получала `role="img"` с той же подписью, что и стоящий рядом текст. Скринридер читал «Жаңа шығарма Жаңа шығарма». Ни один вызов в проекте не передаёт `label` иконке осознанно — все 185 включений были уязвимы, все такие имена были утечкой.
- `TabRolesPromiseAPanel` — `role="tab"` без `role="tabpanel"` на той же странице. Роль обещает связанную через `aria-controls` панель и переключение стрелками без перезагрузки; `segmented_control.html` носил `role="tablist"` и `role="tab"`, будучи обычной навигацией по `?tab=` с полным перезапросом. NVDA объявлял «вкладка 1 из 4», стрелка не делала ничего — на профиле, чужом профиле и в библиотеке. Проверка общая: настоящий `tablist` в проекте появиться может, но только вместе с панелью.
- `IconLabelsDoNotDuplicateText` — та же ошибка, пойманная по отрендеренному DOM: если имя `<svg role="img">` совпадает с текстом его контейнера, имя лишнее. Нужен обоими концами: `only` закрывает известный путь утечки, эта проверка — любой другой.
- `GenericElementsCarryNoAriaLabel` — `aria-label` на `<span>` или `<div>` без роли. У обоих роль `generic`, а имя ARIA разрешает выставлять только элементам с ролью, поддерживающей именование: атрибут виден в разметке и отсутствует в озвучке. Так пропали два признака сразу — точка «оқылмаған» на уведомлении, единственное отличие непрочитанного для незрячего, и счётчик ұнату в списке глав, где цифра вдобавок стояла под `aria-hidden`, то есть строка не озвучивалась вообще. Правило было записано для `stat_pill` и не соблюдалось больше нигде. Лечение — `sr-only` рядом, сам элемент под `aria-hidden`; аватар вместо подписи ушёл под `aria-hidden` целиком: имя автора во всех вызовах стоит соседним текстом, и подпись была бы вторым его прочтением.

Правила продублированы в `CLAUDE.md`, но живут именно здесь: документ можно не прочитать, тест — нет.

Многострочная документация в шаблонах пишется через `{% comment %}…{% endcomment %}`.

### `test_desktop_layout.py` — брейкпоинты каркаса

Из docstring: «правый рейл — единственный элемент, который сужает колонку контента, поэтому его брейкпоинт держим в одном месте и проверяем, что все спутники переключаются вместе с ним. Рассинхрон даёт либо дырку в контенте, либо один и тот же блок дважды на экране».

Единственный файл, которому **разрешено** читать классы Tailwind — предмет проверки и есть раскладка.

| Класс | Что держит |
|-------|-----------|
| `BookGridSizing` | Карточка на десктопе не мельче, чем на телефоне. Регрессия: шесть колонок в узкой колонке давали 89px обложку при ширине 1024 |
| `ContentColumnWidth` | Колонка контента — 860px с рейлом и без него. Регрессия: ниже `xl` контент забирал место рейла и становился шире (1184), чем на большом экране (860) |
| `RailBreakpointConsistency` | `<aside>` включается на `xl`, не на `lg`; ни один шаблон не гейтит контент рейла по `lg` |
| `HeaderAlignment` | Контейнер шапки = контейнер страницы; шапка не имеет собственных паддингов |
| `RailContentHasMobileEquivalent` | Ни один виджет не эксклюзивен для рейла — до `xl` он обязан быть в потоке |
| `ProfileStatsNotDuplicated` | Обратная сторона: блок не рендерится дважды на широком экране |
| `MoneyFormatting` | Приз проходит через фильтр `spaced`; сырой `stringformat` запрещён (BR-42) |
| `HomeRowSize` | Ряд несёт пять карточек, сетка — пять колонок, скелетон повторяет сетку контента |

Все семь — про инварианты, невидимые в юнит-тесте отдельной страницы и заметные только на реальной ширине экрана. Их стоит расширять при каждом новом виджете рейла.

### `test_docs_sync.py` — синхронизация ТЗ с кодом

Третий файл того же рода: он проверяет не продукт, а **документацию о продукте**. Появился после ревизии, которая нашла 26 расхождений между `docs/` и кодом — все накопились незаметно, потому что документ выглядит одинаково авторитетно и через день, и через три месяца.

Проверить документацию на правдивость целиком невозможно. Но её проверяемая часть — имена файлов, токенов, хелперов и счётчики — это ровно то, на чём ТЗ и разъехалось.

| Класс | Что держит | Что поймало бы |
|-------|-----------|----------------|
| `TestCounters` | Счётчики тестов, тест-файлов и компонентов в `README.md` и `CLAUDE.md` | «883 тестов в 16 файлах» при фактических 429 в 16; «~55 компонентов» при 50 |
| `TestReferencedPathsExist` | Каждый путь к файлу, упомянутый в ``…``, существует | Ссылки на удалённые `catalog_controls.html`, `sidebar.html`, `search_results.html` |
| `TestDesignTokens` | Каждый токен `--color-*` / `--radius-*` / `--shadow-*` / `--font-*` объявлен в `@theme` | Главное расхождение дизайн-системы: «--teal» вместо `--color-brand` |
| `TestDataContract` | Хелперы из [12 §12.3](12-domain-model-contract.md) достаются через `core.data` | Контракт для Ф14, называвший восемь несуществующих функций |
| `TestDecisionsAreDefined` | Каждый упомянутый `DEC-NN` определён в реестре [10](10-resolved-decisions.md) | Решение, принятое мимо реестра, или опечатка в номере |
| `TestStatusLabels` | Тексты статусов в ТЗ совпадают с `components/status_badge.html` | Расхождение в трёх из пяти: «Жарияланбаған» vs «Жоба» |
| `TestDocsAreStamped` | У каждого модуля есть шапка «Обновлён / Сверен с кодом» | Документ без даты, по которому не понять, что устарело |

**Чего он не проверяет и проверить не может** — соответствие описания поведению. Если FR говорит «кнопка синяя», а она бирюзовая, поймают только глаза. Страж держит имена и числа, не смысл.

Ложные срабатывания лечатся не ослаблением проверки, а уточнением: URL-маршруты (`/api/search-index.json`) отсеиваются по ведущему слэшу, префиксы токенов (`--color-*`) — по завершающему дефису, пути-примеры с `<плейсхолдерами>` — по угловым скобкам. Список `ALLOWED_MISSING` — для файлов, которых заведомо нет на диске (`output.css` gitignored).

## 15.5 Что считать регрессией

| Симптом | Скорее всего |
|---------|--------------|
| Падает `test_urls_smoke` | Сломан `{% url %}`, отсутствует партиал или упал фильтр |
| Падает `test_corpus` | Демо-корпус потерял инвариант: реакции разошлись с главами, в подборке черновик, работа обещает главы без текста |
| Падает `test_template_lint` | Многострочный `{# #}` / `{% %}` (текст утечёт на страницу), Alpine-директива вне `x-data` (элемент мёртвый), `icon.html` без `only` (подпись прозвучит дважды) или `role="tab"` без панели |
| Падает `test_desktop_layout` | Разъехались брейкпоинты рейла или сетка рядов |
| Падает `*Empty` или `*Unknown` | Сломано вырожденное состояние — обычно самое заметное для пользователя |
| Падает `test_states` | Нарушен контракт DEC-17 (`?state=loading\|error`) |

**Тест не чинится подгонкой под новое поведение**, если он кодирует решение из [10](10-resolved-decisions.md) или §15.4. Сначала пересматривается решение — новым DEC, — потом тест.
