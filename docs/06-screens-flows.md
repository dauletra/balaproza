## 6.3 Ключевые сценарии (user flows)

### Сценарий A — Читатель находит и читает
1. Заходит на главную → видит редакционную витрину.
2. Через жанр-чип / поиск / «книгу недели» открывает произведение.
3. Жмёт «Оқу» → режим чтения, настраивает шрифт/тему.
4. (Гость при попытке лайкнуть/комментировать) → Login modal → вход через Telegram.
5. Сохраняет в библиотеку → произведение в «Оқу үстіндегі».
6. Возвращается позже → главная предлагает «Жалғастыру оқу».

### Сценарий B — Читатель становится автором
1. Авторизованный читатель жмёт CTA «Шығарма жазу» / «Стань автором».
2. (Автоматически получает роль Автор — DEC-01.)
3. Заполняет New story: название, аннотация, жанр(ы), статус.
4. В редакторе глав пишет первую главу, сохраняет/публикует.
5. Произведение уходит на модерацию (Тексеруде).
6. После одобрения — статус «Жарияланған», появляется в каталоге.

### Сценарий C — Автор участвует в конкурсе
1. На главной видит hero активного конкурса → детальная.
2. Изучает условия, таймлайн, жюри, призовой фонд.
3. «Қатысу» → форма подачи: выбирает своё произведение.
4. Система проверяет чек-лист (объём 5 000–15 000 знаков, язык, оригинальность, AI-декларация, возраст 14–18).
5. Подаёт (одна работа на конкурс — BR-23).
6. Отслеживает статус в «Мои заявки» (reviewing → accepted).

### Сценарий D — Пользователь идёт в «Авторлар мектебі»
1. В footer (или блоке на главной/рейле) видит «Авторлар мектебі» — набор ссылок.
2. Выбирает нужный канал (YouTube — вебинары, Instagram — интервью, TikTok — советы, Telegram — анонсы).
3. Переходит на внешний ресурс в новой вкладке. Контент смотрит вне платформы (DEC-02).

## 6.4 Состояния экранов (states)

Для каждого списочного экрана обязательны состояния:

| Состояние | Где применяется |
|-----------|-----------------|
| **Loading** | все экраны с данными (скелетоны/спиннер) |
| **Empty** | My stories, Notifications, Library (вкладки), результаты поиска, My submissions |
| **Error** | сбой загрузки данных (сообщение + повтор) |
| **Content** | основной вид с данными |
| **Gated** | для гостя там, где нужен вход (CommentLoginGate, Login modal) |

> ✅ **Решение DEC-17.** Loading- и Error-состояния в прототипе отсутствовали (данные захардкожены). В ТЗ они **обязательны** для всех экранов, зависящих от данных.
