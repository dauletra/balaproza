# Архитектура

Что такое Qazaqnovel, из чего она собрана, какие инварианты нельзя нарушать.

## Продукт

Литературная UGC-платформа на казахском: чтение, письмо, конкурсы. Школа
авторов — внешние каналы, на сайте только блок ссылок. Возрастного ценза у
платформы нет, вилку ставит конкретный конкурс.

Входит: авторизация, главная, каталог, страница произведения, авторский
кабинет, профиль, библиотека, уведомления, конкурсы, правовые стабы.
Не входит: монетизация, личные сообщения, нативные приложения, кастомный UI
модерации помимо `/moderation/`, страница школы.

## Стек

Django 6, серверный рендеринг · PostgreSQL · Tailwind v4 (`@theme` в
`static_src/input.css`, конфига нет) · Alpine.js 3 и htmx 2 self-hosted ·
self-hosted шрифты. Сборщика, ES-модулей и клиентского стора нет. Свой JS —
файлами в `static/js/` (`Alpine.data` по имени).

## Слои

```
core/domain/    правила: константы и чистые функции, моделей не знает
core/managers.py  выдача: StoryQuerySet/ContestQuerySet — публичность, карточка, оси, фазы
core/queries/   записи: выдача из менеджеров, справочники, мутации
                (в т.ч. notifications.py — лента и события, её наполняющие)
core/data.py    фасад — единственная дверь к данным
core/links.py   CatalogState, CATALOG_AXES, сборка ссылок
core/views/     модуль на раздел
templates/      корневая templates/, не core/templates/
```

Инварианты: `core/domain` не импортирует модели/`core.data`/корпус (иначе
цикл импортов); читают и пишут только через `core.data`; `_corpus.py` читает
только `seed_demo`; URL строит только `links.py`.

## Данные

Поля и причины — в `core/models/`. Здесь то, чего список полей не выражает.

| Модель | Что нельзя сломать |
|---|---|
| **User** | Ни возраста, ни пола, ни настоящего имени — не хранятся вовсе. Роли «читатель» нет: вошедший читает, пишет, комментирует, подаёт на конкурс. `followers` пересчитывается по `Follow` |
| **Genre** | Закрытый справочник 12 |
| **Tag** | До 10 на работу, `pending → accepted\|rejected`, счётчики — аннотации |
| **Story** | Публичность — `PUBLIC_STATUSES`, не литерал `'Published'`. `format` выбирает автор. Число частей — производное |
| **Chapter** | Текст в `body`. Чтение через `?chapter=N`, отдельного маршрута нет |
| **Contest** | Три даты; фаза, отсчёт, год, число заявок — выводятся |
| **Submission** | Одна на автора и конкурс |
| **LibraryEntry** | Три полки; закладку держит `ReadingProgress` |
| **StoryComment** | Один уровень ответов |
| **Notification** | Хранит момент, а не «как давно»; ведёт к предмету. Пишется действием, не сигналом: адресата знает действие. `pushed_at` — очередь доставки в Telegram, отдельной таблицы у неё нет |

**Производное не хранится** — расходится молча («87 өтінім» при одной
заявке). Исключения: акты с датой и автором (`AwardGrant`,
`Notification.outcome`) и колонки под `ORDER BY`/`WHERE` (`Story.likes`,
`User.followers`, `Story.recent_views`) — пересчитываются по строкам.

**Аннотация или fallback**: `chapter_count`, `effective_chars`, `my_reaction`
и подобные приезжают с выдачей (`with_reading_effort()`); забытая аннотация —
молчаливый N+1, ловит `test_query_budget`.

**Хелпер отдаёт QuerySet, не список** — список платит запросом сразу, даже
если страница его не покажет.

## Связи

```
User (1) ──< (N) Story ──< (N) Chapter
Story (N) >── (1..2) Genre          основной + до одного дополнительного
Story (N) >──< (N) Tag              до 10
Story (1) ──< (N) StoryComment ──< ответы, один уровень
User (1) ──< (N) LibraryEntry ──> (1) Story     saved | reading | done
User (1) ──< (N) ReadingProgress ──> (1) Story
User (N) >──< (N) User              Follow
Contest (1) ──< (N) Submission ──> (1) Story
Contest (1) ──< (N) ContestAward ──< (N) AwardGrant ──> (1) Story
Collection (1) ──< (N) CollectionItem ──> (1) Story    редакционная курация
Notification (N) >── (1) User       опц. ссылки на actor / Story / Contest
```

## Роли и доступ

Гость читает публичное. Вошедший — автор целиком: чтение, лайки, комментарии,
библиотека, подписки, жалобы, кабинет, подача на конкурс; правит только своё.
Модератор — `/moderation/` (решения, жалобы) плюс Django admin (справочники,
конкурсы, жинақтар; требования к ней — в [`spec.md`](spec.md), «Админка»).

Приватное — у владельца: библиотека, прогресс чтения, комментарий жюри.
Подписчики и подписки публичны.

## Авторизация

Сессия — `django.contrib.auth`, `request.user`. Слой данных принимает
пользователя, не ник: `None` значит «гость». Снимок автора живёт на объекте
(`User.authored`, `shelf()` и другие `cached_property`) — один запрос на всю
страницу профиля.

Провайдер личности — Telegram Login Widget, redirect-режим: подпись проверяет
`domain.telegram.verify_telegram_auth` (HMAC, без Django). `telegram_id` —
связь при повторном входе, не публичный идентификатор; `username` нового
аккаунта — случайный `id<6 цифр>`. `terms_accepted_at` — единственный признак
завершённой регистрации; `OnboardingGuardMiddleware` держит гейт на каждом
запросе, не только на первом редиректе.

Тот же бот и тот же `telegram_id` служат обратным каналом: виджет входа
просит право писать, `domain.telegram.send_telegram_message` им
пользуется, `manage.py push_notifications` разбирает очередь раз в минуту.
Оба конца — в одном модуле домена: Telegram здесь внешний протокол, а не
часть предметной области портала.

Первый визит `User` не заводит: `telegram_callback` находит подтверждённый
`telegram_id` в базе (`find_telegram_user`) — если его там нет, кладёт в
`request.session['pending_telegram_id']` и ведёт на анкету анонимным.
`get_or_create_telegram_user` вызывается один раз, из `onboarding`, и только
на валидном сабмите — до этого момента отказаться (`decline_onboarding`)
значит просто забыть ключ сессии, без каскада удаления. Тот же
`decline_onboarding` закрывает и соседнее состояние — уже вошедшего без
анкеты (`terms_accepted_at` пуст) — тем же приёмом, что `delete_account`:
аккаунт там уже существует, и «бас тарту» его стирает.

## Тестирование

`core/tests/` — класс на вопрос, один запрос в теле теста. Точечные данные —
`factories.py`, корпус — для объёма (смоук, бюджет запросов). Логин —
`login_as`/`login_as_newcomer`, подделывать сессию нельзя.
