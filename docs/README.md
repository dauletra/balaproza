# Документация Balaproza

Balaproza — казахоязычный литературный портал: дети, подростки и молодые взрослые
читают произведения сверстников и публикуют свои.

| Файл | О чём |
|---|---|
| [`architecture.md`](architecture.md) | Продукт, стек, слои, инварианты данных, роли, авторизация |
| [`spec.md`](spec.md) | Требования: FR по модулям, BR, NFR |
| [`ui.md`](ui.md) | Токены, OKLCH-реестры, каркас и навигация, правила компонентов, тон интерфейса |
| [`10-resolved-decisions.md`](10-resolved-decisions.md) | **Реестр решений DEC** — почему код такой |
| [`../README.md`](../README.md) | Установка, ежедневная работа, деплой, чек-лист запуска |

Рабочие заметки для агента — [`../CLAUDE.md`](../CLAUDE.md), это не спецификация.

## Правила работы с документами

1. **Номер не переиспользуется.** Аннулированное FR/BR/DEC остаётся аннулированным:
   на него ссылаются комментарии, коммиты и внешние материалы.
2. **Решение не правится — оно отменяется новым.** DEC со ссылкой «отменяет DEC-NN»,
   старый помечается перечёркнутым. История решений и есть ценность реестра.
3. **Невыполненное помечается ⛔ с объяснением** — иначе документ выглядит описанием
   факта. Так помечены NFR-25, NFR-30, NFR-41, DEC-12.
4. **Изменение, затрагивающее FR/BR/DEC, правит документ тем же коммитом.** За три
   коммита без этого правила ТЗ разошлось с кодом в 26 местах.

Прежние 21 модуль (00–20) слиты в четыре файла выше: карта реализации и контракт
тестирования удалены — их работу делает поиск по коду, а завершённые планы миграций
живут в git log.
