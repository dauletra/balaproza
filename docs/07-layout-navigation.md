# 07 · Каркас и навигация

> `Обновлён: 2026-08-21` · `Сверен с кодом: fdde268`

## 7.1 Каркас страницы (`templates/base.html`)

Постоянная рамка, наполняемая контентом. Отдельных десктопного и мобильного каркасов нет — это одна адаптивная вёрстка (DEC-03). Левый sidebar исключён (DEC-25). В хедере остаются два главных продуктовых входа: «Оқу» (`/catalog/`) для чтения и «Байқаулар» для конкурсов. Footer работает как карта сайта. Меняется только контентная область и правый рейл (опционально).

```
┌─────────────────────────────────────────────────────────────┐
│ Header  64px  (sticky)                                      │
│ [Logo]  [Іздеу 520px]  [Байқаулар]                          │
│         [Шығарма жазу]  [Хабарлама +N]  [Аватар ▾] / [Кіру] │
├───────────────────────────────────────────┬─────────────────┤
│ Контент (max-w-860, min-w-0, flex-1)      │ RightRail       │
│ центрируется, когда рейла нет             │ 300px, опц.,    │
│                                           │ только xl+      │
├───────────────────────────────────────────┴─────────────────┤
│ Footer — карта сайта (Байланыс / Контент / Сайт /           │
│ Құжаттар + Авторлар мектебі) + соцсети + ТАРАЗ 2024         │
└─────────────────────────────────────────────────────────────┘
```

**Параметры:** `has_right_rail` (bool, страница передаёт через context). При `False` правый `<aside>` не рендерится. Контейнер: `max-w-[1280px]`, padding `lg:px-12`.

**Ширина колонки контента фиксирована — `max-w-[860px]` на `<main>`, `mx-auto`.** 860 = 1184 (контейнер минус `lg:px-12`) − 300 (рейл) − 24 (gap), то есть ровно та ширина, которую колонка имеет рядом с рейлом. Без рейла — ниже `xl` или на странице с `has_right_rail=False` — колонка не растягивается на освободившееся место, а центрируется в контейнере. Иначе контент на меньшем экране становился **шире**, чем на большом (1184 против 860), и сетка карточек меняла масштаб при сужении окна. Регрессия закрыта классом `ContentColumnWidth` в `core/tests/test_desktop_layout.py`; он же запрещает шаблонам страниц объявлять свой `max-w-[Npx]` больше 860.

## 7.2 Шапка (`partials/header.html`)

Однострочная, h=64px, `sticky top-0`. Состав слева направо:

| Элемент | Спецификация |
|---------|--------------|
| Логотип | кликабелен → главная |
| Поиск | 520×35, radius 24, фон `--color-slate-100`, плейсхолдер «Шығарма немесе автор іздеу...». Клик/фокус → открывает Cmd+K popup |
| Байқаулар | единственная контентная ссылка в нав-кластере (DEC-25). Активный стейт — `text-brand`, иначе `text-slate-700 hover:text-brand` |
| CTA «Шығарма жазу» | иконка pen + текст, `--color-brand` |
| Уведомления (auth) | колокольчик + красный счётчик непрочитанных; `aria-label` с числом. **Единственная точка показа счётчика** — в mobile bottom nav уведомлений нет |
| Профиль (auth) | аватар 36 + chevron → dropdown (Профиль / Менің шығармаларым / Кітапхана / Менің заявкаларым / Шығу). Каждый пункт с slim-иконкой слева |
| Кіру (гость) | вместо аватара — текстовая ссылка `text-brand` |

Контейнер шапки повторяет контейнер страницы (`max-w-[1280px]` и те же боковые поля), чтобы логотип и контент стояли по одной вертикали. Регрессия закрыта тестом `test_header_container_matches_page_container`.

## 7.3 Левый сайдбар (исключён — DEC-25)

На десктопе левый sidebar отсутствует. Главный вход в чтение — «Оқу» в header (`/catalog/`). Жанры остаются обзорной страницей и секцией главной, а Жинақтар — отдельным editorial-разделом в footer. Конкурсы — отдельная ссылка в хедере.

На mobile навигация — bottom nav из 5 слотов (7.6).

## 7.4 Правый рейл (сменный)

> ✅ **Решение DEC-18.** Правый рейл **не содержит соцсети** (закрывает UX-аудит «Right rail»: соцсети как костыль контент-стратегии). Соцсети переносятся в footer. Правый рейл несёт продуктовые блоки в зависимости от контекста страницы:

| Контекст | Содержимое рейла (сверху вниз) |
|----------|-------------------------------|
| Главная | Активный конкурс → «Танымал тегтер» → блок ссылок «Авторлар мектебі» |
| Каталог (search/genre/tag/catalog, DEC-27) | `_filter_panel` — sort, status, search refining, genre chip-cloud, popular tags. Та же панель открывается на mobile через bottom-sheet по `open-catalog-filters` |
| Страница произведения (в т.ч. при открытой главе) | Карточка автора + оглавление глав |
| Авторский кабинет | Статистика писателя |
| Профиль, конкурсы | Контекстные продуктовые блоки |

> **Правило против дублей.** Всё, что показывает рейл, обязано быть доступно и без него — рейл виден только с `xl`. Секции главной, продублированные рейлом (баннер конкурса, «Танымал тегтер»), помечены `xl:hidden`, чтобы на широком экране один блок не показывался дважды. Оба инварианта закрыты тестами `test_no_widget_is_rail_exclusive` и `test_stats_render_once`.

> ✅ **Решение DEC-27 (выдержка).** На каталог-страницах рейл становится фильтр-панелью. На mobile та же панель доступна через bottom-sheet (партиал `_filter_sheet`, триггер — кнопка «Сүзгілер» в основном контенте, событие `open-catalog-filters`). Контейнер рейла расширен с 234px до 300px ради осмысленных виджетов.

## 7.5 Footer (`partials/footer.html`)

После DEC-25 footer служит «картой сайта» — здесь живут все контентные разделы, не помещённые в навигацию хедера. Фон `--color-slate-100`, padding `lg:px-12`. Четыре колонки на lg+, 2 на sm-md, стек на mobile:

1. **Байланыс** — email + иконки соцсетей (YouTube, Instagram, TikTok, Telegram).
2. **Контент** — Жанрлар · Жинақтар · Байқаулар.
3. **Сайт** — Проект туралы · Жариялау шарттары · Модерация ережелері.
4. **Құжаттар + Авторлар мектебі** — Пайдалану ережелері · Құпиялылық саясаты + inline-блок 4 внешних ссылок школы (рендерится через `components/school_links.html` с `layout="inline"`).

Низ: разделитель + копирайт «ТАРАЗ 2024» по центру.

> ✅ **Решение DEC-19 (ред. для MVP).** Соцсети размещаются в footer и в блоке «Авторлар мектебі». Весь образовательный контент (видеолекции, вебинары, интервью, курсы) живёт **на внешних каналах** и смотрится вне платформы — встраивание видео на сайт в MVP не делается (DEC-02/DEC-22). Instagram/TikTok/Telegram/YouTube — каналы дистрибуции, на которые ведут ссылки.

## 7.6 Мобильная навигация

### Шапка на mobile (h=64)
Тот же `partials/header.html`, сжатый брейкпоинтами: логотип с подзаголовком + иконка поиска (открывает quick-search popup). Нижняя граница `--color-slate-200`.

### Нижнее меню (`partials/mobile_nav.html`) — плавающая пилюля 360×64, `rounded-pill`, `bottom-4`, скрыта с `md`

Пять слотов, набор зависит от роли:

**Гость:**
```
[ Басты ] [ Оқу ] [ (Іздеу) ] [ Байқау ] [ Кіру ]
```

**Авторизованный:**
```
[ Басты ] [ Кітапхана ] [ (Жазу) ] [ Байқау ] [ Профиль ]
```

- **У каждого слота, кроме FAB, видимая подпись 10px.** Иконочная навигация без подписей опирается на неочевидные метафоры; при 360px на слот приходится 72px — короткие казахские слова помещаются, высота 64 сохраняется (22 + 2 + 10 = 34). У FAB подписи нет, только `aria-label`.
- Центральная кнопка-FAB — круг `--color-brand` (DEC-06: бирюзовый, не синий).
  - **У гостя FAB — поиск**, а не логин. Самый заметный слот меню не должен требовать регистрации до того, как человек получил хоть какую-то ценность. Клик открывает quick-search popup; `href` на `/search/` работает как no-JS fallback. Логин уехал в пятый слот, который прежде дублировал поиск.
  - У авторизованного FAB — создание произведения.
- **«Оқу» у гостя ведёт на `/collections/`, а не в каталог** (DEC-31). Гостю без сформулированного запроса нужен вопрос «что ты хочешь читать», а не сетка из всего портала; полный каталог остаётся доступен из жинақтар, поиска и жанровой полосы. Подпись слота и иконка `book` не меняются — меняется только цель.
- Конкурсы — иконка `trophy` (та же, что в хедере), не `adjustments`.
- Активный пункт — `text-brand`; неактивные — `text-slate-800`. Тень `--shadow-bottom-nav`.
- **Кітапхана** у авторизованного входит в bottom nav как главный возврат к чтению. `my_submissions` не входит в 5 слотов и остаётся доступен через avatar-dropdown и конкурсные страницы.
- **Уведомлений в нижнем меню нет** — колокольчик со счётчиком живёт в хедере (7.2).

### Режим чтения: меню уступает место панели чтения

Страница произведения шлёт `reading-mode` (`{ on: bool }`), когда текст главы входит в кадр и когда уходит из него. `mobile_nav.html` слушает это окно-событие и убирает пилюлю сдвигом вниз (`translate-y-28 opacity-0 pointer-events-none` + `aria-hidden`), а на её место встаёт **панель чтения** — та же геометрия 360×64, `bottom-4`, `rounded-pill`, `--shadow-bottom-nav`.

Причина: две плавающие пилюли на 375px встают одна на другую. Прячем сдвигом, а не `display:none` — возврат меню при выходе из главы должен читаться как движение, иначе оно «мигает» обратно.

Состав панели (слева направо): `Aa` — настройки чтения (FR-STORY-07), `N / M` — оглавление глав bottom-sheet'ом, «Келесі» — следующая глава. По верхнему краю пилюли — линия прогресса по тексту текущей главы. Для `format=single` вместо оглавления и перехода — процент прочитанного.

Панель — единственный случай, когда нижнее меню скрывается; на всех остальных страницах оно постоянно.

## 7.7 Жанровая полоса

Реализована как `partials/home/genre_strip.html` (FR-HOME-06) — полоса чипов сразу под hero главной, ~44px: цветная точка по `Genre.hue`, клик ведёт на `/genres/<slug>/`, замыкающая ссылка — на `/genres/`. Отдельной полосы-строки в шапке нет — она уехала в контент главной вместе с остальной контентной навигацией (DEC-25).

**Жанр — вывеска, а не дверь (DEC-31).** Полоса не ведёт навигацию: её работа — за пару секунд объяснить, что это литературный портал. Навигацию ведут жинақтар («зачем читать сейчас») и теги («о чём это»). Прежняя секция `genres_section` — заголовок, чипы и скроллер произведений активного жанра — стоила ~330px в середине страницы; она удалена вместе с параметром `?genre=`. Цветовая система по `Genre.hue` при этом не меняется: жанр остаётся чипом на каждой обложке, цветом плашки в `cover_placeholder` и фильтром в каталоге ([03](03-genre-color-system.md)).

> ✅ **Решение DEC-20.** Плоская текстовая полоса жанров заменена цветными чипами OKLCH (DEC-11/DEC-14), что закрывает находку UX-аудита: «жанры должны выглядеть как приглашение, а не меню фильтров».

Страница произведения и профиль используют **sticky scrollspy** (пилюли-якоря с подсветкой активной секции через IntersectionObserver) вместо декоративных табов (DEC-15).
## 7.9 Мобильные сүзгі каталога

Каталог — единственная страница, где фильтр это основной инструмент, а не украшение рейла. На `xl+` панель живёт в правом рейле (`partials/right_rail/catalog.html`), ниже — в bottom-sheet. Раскладка мобильного каталога держится на трёх решениях:

1. **Липкая панель управления** `sticky top-16 z-20` (высота шапки — 64px, её `z-30` выше). Раньше кнопка сүзгі и счётчик стояли статично и уезжали после первой карточки: сменить сортировку значило проскроллить наверх и обратно.
2. **Сортировка снаружи модалки** — нативный `<select>` прямо в панели. Это самая частая ось, и прятать её за листом стоило двух тапов и перезагрузки. Нативный селект открывается системным пикером, а не самодельным дропдауном.
3. **Ряд чипов активных осей** под панелью: каждый чип снимает свою ось, `Тазалау` появляется от двух и больше. До этого снять одну ось было нельзя — только сбросить всё, и на телефоне ещё и из-под модалки.

**Лист копит черновик.** `_filter_panel.html` принимает `variant`: `rail` сабмитит по `@change` (ничего не перекрыто, результат виден сразу), `sheet` — нет. Автосабмит в модалке означал навигацию после каждого тапа, а вместе с навигацией исчезал и сам лист: пять осей стоили пяти перезагрузок и пяти открытий. Применяет всё кнопка «Нәтижелерді көрсету»; она стоит **после** жанров и тегов и связана с формой через `form=`, иначе переставала быть видимой ровно там, где список ещё продолжается.

**Оси — чипы, а не вертикальные radio-списки.** У `h-3.5 w-3.5` радиокнопки внутри `inline-flex`-подписи реальная цель была ~20px, а пять групп подряд давали 19 строк, которые не помещались в экран. Чип держит `min-h-11` в листе и `min-h-9` в рейле и укладывается в ряды.

Жанр и тег остались **ссылками**, а не полями формы: это разделы с каноническим URL, и один тап по ним — законная навигация. Состояние остальных осей они теперь несут с собой ([14 §14.4](14-implementation-map.md)).
