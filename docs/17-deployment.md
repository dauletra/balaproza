# 17 · Деплой и эксплуатация

> `Обновлён: 2026-08-25` · `Сверен с кодом: 97aab90`

Что нужно сделать, чтобы проект работал не на `runserver`. Документ покрывает пробел, который [09 §9.7](09-nonfunctional.md) обозначал одним требованием NFR-65: список настроек был, процедуры не было.

> **Статус: проект в production не разворачивался.** Ниже — не журнал существующего окружения, а требования и порядок первого деплоя. Значения, помеченные ⚠️, обязаны быть выставлены до того, как сайт станет публичным.

## 17.1 Что сейчас в `config/settings.py`

Файл — результат `django-admin startproject`, отредактированный минимально. Для прода он **не готов**, и это нормально для дизайн-фазы; важно, чтобы это было записано.

| Настройка | Сейчас | Для прода |
|-----------|--------|-----------|
| `SECRET_KEY` | `SECRET_KEY` из окружения, иначе dev-литерал `django-insecure-…` | ⚠️ Задать в окружении. Ключ из git считается скомпрометированным — сгенерировать новый |
| `DEBUG` | `DJANGO_DEBUG`, по умолчанию `1` | ⚠️ `DJANGO_DEBUG=0`. При `True` Django отдаёт трейсбеки с содержимым настроек |
| `ALLOWED_HOSTS` | `DJANGO_ALLOWED_HOSTS` через запятую, по умолчанию пусто | ⚠️ Список доменов. При `DEBUG=False` пустой список отдаёт 400 на любой запрос |
| `DATABASES` | PostgreSQL, строка подключения в `DATABASE_URL` (обязательна) | Тот же код, другое значение переменной. Бэкап — `pg_dump` по расписанию |
| `LANGUAGE_CODE` | `kk` | Без изменений |
| `TIME_ZONE` | `Asia/Almaty` | Без изменений |
| `USE_TZ` | `True` | Без изменений |
| `STATIC_URL` | `static/` | Добавить `STATIC_ROOT` — без него `collectstatic` не работает |
| `STATICFILES_DIRS` | `[BASE_DIR / 'static']` | Без изменений |
| `MEDIA_URL` / `MEDIA_ROOT` | `/media/`, `BASE_DIR / 'media'` | Раздаёт веб-сервер, не Django (см. 17.4) |
| Security-заголовки | **отсутствуют** | Блок из 17.3 обязателен |

**Ничего из этого не правится в `config/settings.py` жёстко.** Значения, различающиеся между машинами, читаются из окружения; в git попадает только код чтения.

Окружение живёт в `.env` рядом с `manage.py` — его подхватывает `python-dotenv` при старте настроек. Файл в `.gitignore`; версионируется образец `.env.example`, и он же служит списком того, что вообще настраивается. На сервере `.env` не обязателен: переменные могут приходить от менеджера процессов, код читает и то и другое одинаково.

`DATABASE_URL` — **единственная обязательная**: без неё настройки падают с `ImproperlyConfigured` и подсказкой скопировать образец. Тихого отката на локальную БД нет намеренно — он означал бы, что прод при опечатке в переменной поднимается на пустой базе вместо отказа.

### Что ещё не сделано

- `INSTALLED_APPS` не содержит `django-debug-toolbar` — группа `dev` установлена, но не подключена. Если её подключат, обязательно под `if DEBUG`.
- Логирование не настроено: при `DEBUG=False` ошибки уйдут в никуда. Минимум — `LOGGING` с выводом в stdout, чтобы их подхватил менеджер процессов.
- `config/wsgi.py` — дефолтный, менять не нужно.

## 17.2 Зависимости

**Python** — через `uv`, группы объявлены в `pyproject.toml`:

| Группа | Состав | Когда |
|--------|--------|-------|
| основная | `django>=6.0.5`, `psycopg[binary]`, `dj-database-url`, `python-dotenv` | всегда |
| `dev` | `django-debug-toolbar>=6.3.0` | локальная разработка |
| `prod` | `gunicorn>=26.0.0` | сервер |

`psycopg[binary]` тянет собранный драйвер и не требует компилятора — это то, что нужно на dev-машинах и в контейнере. Если политика сервера запрещает бинарные колёса, ставится `psycopg[c]`, и тогда нужны `libpq-dev` и компилятор.

**Postgres 14+.** Роли нужны права на свою базу, а для прогона тестов — ещё и `CREATEDB`: Django поднимает отдельную `test_<имя>` и сносит её после. Без него `manage.py test` падает на создании базы, а не на тестах:

```sql
CREATE ROLE qnovel_user LOGIN PASSWORD '…' CREATEDB;
CREATE DATABASE qnovel_db OWNER qnovel_user;
```

На проде `CREATEDB` роли не нужен — тесты там не гоняются.

На сервере ставится основная группа плюс `prod`, без `dev`:

```bash
uv sync --no-dev --group prod
```

**Frontend** — Node нужен только на этапе сборки CSS. В рантайме его нет: `output.css` — статический файл.

```bash
npm ci && npm run build
```

`npm run build` — это `tailwindcss --minify` из `static_src/input.css` в `static/css/output.css`.

## 17.3 Обязательные настройки безопасности (NFR-65)

Платформа для детей — эти настройки не опциональны.

```python
SECURE_SSL_REDIRECT = True
SECURE_HSTS_SECONDS = 31536000
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_CONTENT_TYPE_NOSNIFF = True
X_FRAME_OPTIONS = 'DENY'
```

Если Django стоит за обратным прокси (обычный случай), прокси обязан передавать протокол, иначе `SECURE_SSL_REDIRECT` уйдёт в бесконечный редирект:

```python
SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')
```

Перед каждым релизом:

```bash
uv run python manage.py check --deploy
```

Команда проверяет ровно этот список и должна отдавать **ноль предупреждений**. Это единственная автоматическая проверка прод-настроек, которая уже есть в Django — не пропускать её.

### Отдельно про CSP

Проект self-hosted целиком: шрифты в `static/fonts/`, Alpine и htmx в `static/vendor/`, внешних CDN нет. Это делает жёсткий `Content-Security-Policy` дешёвым — стоит выставить его на уровне веб-сервера при первом же деплое, пока не появились внешние скрипты.

Единственный источник инлайн-стилей — OKLCH-цвета жанров ([03](03-genre-color-system.md)), поэтому `style-src` потребует `'unsafe-inline'` либо nonce. Это аргумент в пользу варианта 3 из [03 §3.5](03-genre-color-system.md) — перенести жанровую тему в CSS-переменные.

## 17.4 Статика и media

Это два разных потока, и путают их часто.

**Статика** (`static/`) — код: CSS, шрифты, вендорный JS, логотип. Едет в git (кроме `output.css`), собирается `collectstatic`, раздаётся веб-сервером.

```bash
npm run build
```

```bash
uv run python manage.py collectstatic --noinput
```

Требует `STATIC_ROOT` в настройках. Порядок важен: сначала Tailwind, потом `collectstatic` — иначе соберётся старый или отсутствующий `output.css`.

**Media** (`media/`) — загруженные файлы: обложки произведений. В `.gitignore`, **через git не переезжает**. Сейчас там placeholder-обложки из стороннего источника — [их нужно заменить до публичного запуска](../README.md).

`config/urls.py` раздаёт media только при `DEBUG=True`:

```python
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

В проде это делает веб-сервер. Отдавать media через Django нельзя — это блокирующий воркер на каждой картинке.

`media/` требует резервного копирования: в отличие от статики, восстановить её из репозитория невозможно.

## 17.5 Процедура деплоя

```bash
git pull
```

```bash
uv sync --no-dev --group prod
```

```bash
npm ci && npm run build
```

```bash
uv run python manage.py migrate
```

```bash
uv run python manage.py collectstatic --noinput
```

```bash
uv run python manage.py check --deploy
```

Затем перезапуск gunicorn.

**`migrate` обязателен, даже пока своих моделей нет.** Стаб-логин пишет в сессию, и без таблицы `django_session` вход падает. После Ф14 добавятся миграции моделей, и порядок не изменится.

Gunicorn запускается на `config.wsgi:application` под менеджером процессов (systemd или контейнер), за обратным прокси, который терминирует TLS и раздаёт `/static/` и `/media/`.

## 17.6 Данные

| Что | Откуда берётся | Переживает деплой |
|-----|----------------|-------------------|
| Контент страниц (до Ф14) | `core/stub_data.py`, `core/story_texts/` | Да — это код в git |
| Сессии | `django_session` в Postgres | Да |
| Суперюзер admin | создаётся вручную | Да |
| Обложки, афиши, эмблемы наград | `media/` — загружаются через админку (BR-46: растр, не SVG) | Только при бэкапе |
| `output.css` | `npm run build` | Пересобирается |

`createsuperuser` нужен для Django admin — это единственный инструмент модерации в MVP (DEC-23), в том числе для тегов (BR-TAG-03).

**После Ф14** контент перестанет ехать вместе с кодом. План — management-команда `seed_demo`, идемпотентно раскладывающая те же структуры по моделям: версионируется как код и переживает изменения схемы, в отличие от фикстур.
