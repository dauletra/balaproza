# 01 · Назначение, область охвата и архитектура

> `Обновлён: 2026-08-20` · `Сверен с кодом: 5d39adb`

## 1.1 Назначение продукта

Balaproza — литературная UGC-платформа (user-generated content) для детей и подростков на казахском языке. Продукт решает три задачи:

1. **Чтение.** Дать юным читателям удобную, безопасную среду для чтения произведений сверстников и кураторских подборок.
2. **Творчество.** Дать начинающим авторам инструменты создания, публикации и развития произведений (главы, метаданные, статистика).
3. **Развитие и вовлечение.** Удерживать сообщество внутри платформы через конкурсы; образовательный контент («Авторлар мектебі») на первой версии остаётся за платформой (в соцсетях), а на сайте размещаются ссылки на него.

> ✅ **Решение DEC-02 (стратегическое, ред. для MVP).** В первой версии (MVP) платформа фокусируется на чтении, создании произведений и конкурсах. Образовательный контент — видеолекции, вебинары, интервью, курсы, идеи — **не размещается на платформе**, а живёт во внешних каналах (соцсети). На сайте присутствует **блок ссылок «Авторлар мектебі»** на эти внешние ресурсы. Это сознательное упрощение ради скорости запуска; полноценный раздел школы внутри платформы может появиться в следующих версиях.
>
> Конкурсы, в отличие от школы, реализуются как полноценные разделы сайта (главный канал привлечения авторов).

## 1.2 Целевая аудитория

- **Читатели:** дети и подростки, ориентировочно 10–18 лет.
- **Авторы:** подростки 14–18 лет (нижняя граница согласована с правилами конкурсов, BR-20).
- **Язык интерфейса:** казахский (основной). Контент допускается на казахском и русском (BR-21).

## 1.3 Область охвата (Scope)

### Входит в продукт
Авторизация (Telegram), главная с редакционной витриной, каталог (жанры, коллекции, поиск, **quick-search popup Cmd+K**, **сортировка/фильтры**), страница произведения и режим чтения (включая **share-кнопки** и блок «Басқа шығармалар»), авторский кабинет (создание/редактирование/настройки произведений, редактор глав), профиль (свой и чужой, **редактирование своего**), библиотека, уведомления, конкурсы (список, детальная, подача с **AI-декларацией**, мои заявки), блок внешних ссылок «Авторлар мектебі», **5 правовых/информационных стабов** (модерация, публикация, о проекте, terms, privacy), системные компоненты (toast, модалки, **branded 404/500**, **favicon**).

### Не входит (на данном этапе)
Платные функции/монетизация, личные сообщения между пользователями, мобильные нативные приложения (только адаптивный веб), **кастомный UI панели модератора** (модерация на MVP идёт через стандартный **Django admin** — DEC-23), **внутренняя страница школы авторов с уроками/инструкторами** (на MVP заменена блоком внешних ссылок — DEC-02), полноценный набор SEO-метатегов и OG-изображений (на MVP только favicon + theme-color, см. NFR-62), sitemap.xml/robots.txt (NFR-63).

## 1.4 Платформы и адаптивность

| Брейкпоинт | Целевая ширина макета | Состояние в прототипе |
|-----------|----------------------|----------------------|
| Mobile | 375px | спроектировано (≈14 экранов) |
| Desktop | 1440px | спроектировано (41 экран) |

> ✅ **Решение DEC-03.** Прототип использует абсолютное позиционирование (`left/top` в px) — это артефакт переноса из Figma. В продакшене вёрстка переписывается на **поток (flex/grid) с резиновой сеткой**, фиксированные координаты не переносятся. Десктоп и мобайл — два состояния одной адаптивной верстки, а не два отдельных кодовых дерева. Планшетный брейкпоинт (≈768px) добавляется на этапе верстки как промежуточный.

## 1.5 Техническая архитектура

Прототип был построен на React 18 (UMD) + Babel-in-browser + инлайн-стили и предназначался только для ревью. В продакшен он не переносился.

> ✅ **Решение DEC-29 (отменяет DEC-04).** Реализация — **серверный рендеринг Django-шаблонов**, без JS-сборщика, ES-модулей и клиентского стора. Интерактивность точечная (дропдауны, модалки, автокомплит тегов, quick-search) и покрывается Alpine + htmx. Из DEC-04 в силе остались два пункта: self-hosted шрифты и единый источник токенов в CSS-переменных.

| Слой | Прототип (как был) | Реализовано |
|------|--------------------|-------------|
| Рендеринг | React 18 UMD в браузере | **Django 6**, шаблоны в корневой `templates/`, тонкие view в `core/views.py` |
| Сборка | Babel Standalone в браузере | **Сборки JS нет.** Единственный build-шаг — Tailwind CLI: `npm run dev` (watch) / `npm run build` (`--minify`) |
| Стили | Инлайн + один `styles.css` | **Tailwind CSS v4** через `@tailwindcss/cli`. Все токены — в `@theme` внутри `static_src/input.css`, результат в `static/css/output.css`. `tailwind.config.js` не используется (v4). Инлайн-цвета запрещены, кроме OKLCH по жанровому `hue` (модуль 03) |
| Интерактивность | JSX-состояние | **Alpine.js 3.14.9** (локальное состояние компонентов, глобальные window-события) + **htmx 2.0.4**. Оба self-hosted в `static/vendor/` |
| Состояние/данные | Захардкожено в JSX | `core/stub_data.py` — Python-литералы, читаются напрямую из view. Реальные модели — после Ф14 (модуль [12](12-domain-model-contract.md)) |
| Зависимости Python | — | **uv** (`pyproject.toml`, `uv.lock`); группы `dev` (django-debug-toolbar) и `prod` (gunicorn) |
| Шрифты | Google Fonts с CDN | Self-hosted variable WOFF2 в `static/fonts/` (Montserrat, Open Sans, Inter; Georgia системная) |
| Иконки | SVG-набор в `icons.jsx` | Один SVG-спрайт `templates/components/icons/_sprite.html`, вызов через `components/icon.html` (DEC-09) |

## 1.6 Архитектура каркаса

Все страницы наследуют `templates/base.html`, который задаёт блоки `title`, `content`, `right_rail` и подключает глобальные элементы: спрайт иконок, Alpine/htmx, `toast_host`, `search_popup` (Cmd+K), favicon, theme-color.

- **Каркас:** `partials/header.html` + контентный контейнер `max-w-[1280px]` + опциональный правый `<aside>` 300px + `partials/footer.html` + `partials/mobile_nav.html`.
- **Правый рейл** рендерится **только** если view передал `has_right_rail=True` в контекст, и виден только с брейкпоинта `xl`. Левый sidebar исключён (DEC-25); контентная навигация — секции главной и колонка «Контент» в footer.
- **Mobile:** тот же каркас; хедер сжимается, `mobile_nav` (плавающая пилюля, 5 слотов) показывается до `md`.

Отдельного мобильного дерева шаблонов нет — это одна адаптивная вёрстка (DEC-03). Общий контекст страниц дают три context processor'а в `core/context_processors.py`: `auth_state`, `nav_state`, `site_links`.

Подробно — модуль [`07-layout-navigation.md`](07-layout-navigation.md).
