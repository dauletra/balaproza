# Qazaqnovel

Казахоязычный детский литературный портал. Django 6 + PostgreSQL + Tailwind CSS v4
+ Alpine.js + htmx.

Портал читает и пишет базу на всех путях. Требования и решения — в
[`docs/`](docs/), заметки для разработки — в [`CLAUDE.md`](CLAUDE.md).

## Откуда берутся данные

**Из базы.** Страницы ходят в Postgres через фасад [`core/data.py`](core/data.py):
правила предметной области — из [`core/domain/`](core/domain/), записи — из
[`core/queries/`](core/queries/).

Демо-содержимое кладёт идемпотентная команда `seed_demo`; её литералы лежат рядом
с ней ([`_corpus.py`](core/management/commands/_corpus.py)) и читаются только ею.
Тексты глав — файлами в [`core/story_texts/`](core/story_texts/). 12 жанров и
блок-лист тегов заливает миграция `0002`: они часть системы, а не контент.

## Установка на новой машине

Нужны [uv](https://docs.astral.sh/uv/), Node.js 20+ и PostgreSQL 14+.

```bash
git clone https://github.com/dauletra/qazaqnovel.git
```

```bash
uv sync
```

```bash
npm install && npm run build
```

Роль и база создаются один раз. `CREATEDB` нужен не для сайта, а для тестов:
Django поднимает отдельную `test_<имя>` и сносит её после прогона.

```bash
psql -U postgres -c "CREATE ROLE qnovel_user LOGIN PASSWORD 'сюда-пароль' CREATEDB;"
```

```bash
psql -U postgres -c "CREATE DATABASE qnovel_db OWNER qnovel_user;"
```

Дальше — окружение. `.env` в `.gitignore`, в git лежит только образец:

```bash
cp .env.example .env
```

В нём обязателен один ключ — `DATABASE_URL`. Без него настройки падают
с `ImproperlyConfigured`, а не молча поднимаются на пустой базе.

```bash
uv run python manage.py migrate
```

```bash
uv run python manage.py seed_demo
```

```bash
uv run python manage.py runserver
```

Повтор `seed_demo` не удваивает корпус и возвращает изменённые записи к эталону.
Поэтому команда, а не фикстура: даты идущих конкурсов заданы относительно
сегодняшнего дня, и застывший JSON через месяц перевёл бы конкурс в другую фазу.

## Что не переезжает через git

| Что | Почему | Как восстановить |
|---|---|---|
| `media/` — обложки, афиши, эмблемы наград | в `.gitignore` | Скопировать вручную. Без неё рисуется типографическая плашка OKLCH — страницы не ломаются |
| `static/css/output.css` | пересобираемый артефакт | `npm run build` |
| `.env` | там пароль к БД | `cp .env.example .env` |
| Суперюзер Django admin | живёт в локальной БД | `manage.py createsuperuser` |
| `.venv/`, `node_modules/` | gitignored | `uv sync`, `npm install` |

## Ежедневная работа

```bash
npm run dev
```

Watch-режим Tailwind: пересобирает `static/css/output.css` при правках шаблонов и
`static_src/input.css`. Держать в отдельном терминале рядом с `runserver`.

## Тесты

```bash
uv run python manage.py test core
```

Прогон идёт в четыре процесса, корпус кладётся в базу один раз и приезжает в
каждый клон готовым. Отдельный файл — `test core.tests.test_catalog`,
последовательно — `--parallel 1` (нужен для `--pdb`), быстрый круг без
пересоздания баз — `--keepdb`.

## Вход

Сессию держит `django.contrib.auth`. Провайдер личности — Telegram Login
Widget с проверкой подписи: кнопка ведёт на Telegram, тот
подписывает данные и редиректит браузер на наш callback.

Виджет не рисуется без домена, зарегистрированного за ботом через
`@BotFather` — **на localhost напрямую он не работает даже в разработке**,
нужен туннель (ngrok/cloudflared) с доменом, прописанным боту через
`/setdomain`. Порядок: `@BotFather` → `/newbot` → имя и `@username` бота →
`TELEGRAM_BOT_TOKEN`/`TELEGRAM_BOT_USERNAME` в `.env` → `/setdomain` на
адрес туннеля (для прода — на прод-домен, и тогда переустанавливать при
каждом запуске не надо).

# Деплой

> Проект в production не разворачивался. Ниже — порядок первого деплоя.

## Окружение

Прод включается **одной переменной** — `DJANGO_ENV=production`. Она выключает
`DEBUG`, включает https-редирект, HSTS, secure-куки и `CSRF_TRUSTED_ORIGINS`,
подключает whitenoise (если установлен) и делает `SECRET_KEY` с
`DJANGO_ALLOWED_HOSTS` обязательными: без любой из них запуск падает с
объяснением. Раньше прод отличался тремя независимыми переменными, и любая
забытая давала «почти прод» — трейсбэки на странице или ключ подписи сессий из
репозитория.

`DEBUG_TOOLBAR=0` выключает панель, не трогая `DEBUG`. Значения, различающиеся
между машинами, читаются из окружения — `.env` или менеджер процессов, код читает
и то и другое одинаково.

Ключ из git считается скомпрометированным: в проде генерируется свой.
Логирование настроено (`config/settings.py`, `LOGGING`): `django.request`
пишет в stdout от WARNING и выше — 5xx и необработанные исключения уходят
как ERROR с трейсбеком, 4xx как WARNING. Ротацию и хранение решает
менеджер процессов (systemd/journald или файл, на который смотрит
`StreamHandler`), это не задача Django.

## Зависимости

Группы объявлены в `pyproject.toml`: основная (`django`, `psycopg[binary]`,
`dj-database-url`, `python-dotenv`), `dev` (django-debug-toolbar), `prod`
(gunicorn, whitenoise). На сервере — `uv sync --no-dev --group prod`. Node нужен
только на сборке CSS: в рантайме `output.css` — статический файл.

## Безопасность

Платформа для детей — эти настройки не опциональны:

```python
SECURE_SSL_REDIRECT = True
SECURE_HSTS_SECONDS = 31536000
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_CONTENT_TYPE_NOSNIFF = True
X_FRAME_OPTIONS = 'DENY'
```

За обратным прокси обязателен
`SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')` — иначе
`SECURE_SSL_REDIRECT` уйдёт в бесконечный редирект.

CSP выставляется на веб-сервере при первом деплое. Составлен **по
факту**, а не по намерению: у страницы четыре источника, которые
«жёсткая» политика запретила бы, и каждый из них нужен.

```
default-src 'self';
script-src  'self' 'unsafe-inline' 'unsafe-eval' https://telegram.org;
style-src   'self' 'unsafe-inline';
img-src     'self' data: https://t.me;
frame-src   https://oauth.telegram.org;
connect-src 'self';
font-src    'self';
base-uri    'self';
form-action 'self';
frame-ancestors 'none';
object-src  'none'
```

Почему каждое послабление:

- `https://telegram.org` в `script-src` — виджет входа. Утверждение «внешних
  CDN нет» было неверным с того дня, как появился Telegram-вход;
- `'unsafe-eval'` — Alpine в обычной сборке вычисляет выражения через
  `new Function()`. Убрать можно только перейдя на CSP-сборку Alpine, где
  выражения ограничены; это отдельная работа и не бесплатная;
- `'unsafe-inline'` в `script-src` — инлайновый `<script>` в `base.html`,
  мост из `messages` в тосты. Заменяется nonce, если веб-сервер умеет его
  подставлять;
- `'unsafe-inline'` в `style-src` — OKLCH-цвета жанров вычисляются на
  элементе;
- `frame-src`/`img-src` для Telegram — попап подтверждения входа и аватар.

## Потолок запросов на прокси

Пределы частоты в приложении стоят там, где у действия есть своя строка
в базе: комментарий, жалоба, подписка, реакция — их считает сама таблица
(`core/queries/throttle.py`). Выгрузка текстов ограничена кэшем, одной в
минуту. Автосохранение не ограничено по времени вовсе — автор, пишущий
быстро, упирался бы в такой предел ровно тогда, когда страховка нужнее
всего; вместо этого не пишется то, что не изменилось.

Чего приложение закрыть не может — **аноним**. `/api/search.json` делает
три поиска подстрокой на запрос и входа не требует; считать его по
таблице нечем, а кэш локальный и на четырёх воркерах умножил бы предел на
четыре незаметно. Это работа прокси, и делается она один раз:

```nginx
limit_req_zone $binary_remote_addr zone=qn_api:10m rate=30r/m;
limit_req_zone $binary_remote_addr zone=qn_all:10m rate=600r/m;

location /api/ { limit_req zone=qn_api burst=10 nodelay; }
location /     { limit_req zone=qn_all burst=60 nodelay; }
```

Числа выбраны так, чтобы живой читатель в них не упёрся никогда:
подсказки поиска идут с задержкой в 200 мс после набора, то есть даже
быстрый набор даёт единицы запросов в минуту. Общий потолок закрывает
заодно и то, о чём здесь не подумали.

`SENTRY_DSN` в списке не участвует: туда ходит сервер, а не страница.
`frame-ancestors 'none'` дублирует `X_FRAME_OPTIONS = 'DENY'` — заголовок
старый, директива новая, и обе стоят дёшево.

## Статика и media

**Статика** — код: CSS, шрифты, вендорный JS. Сначала Tailwind, потом
`collectstatic`, иначе соберётся старый `output.css`.

Шрифтов в `static/fonts/` шесть файлов на 1,75 МБ, но читатель скачивает
**два** — `open-sans-variable` и `montserrat-variable`, около 480 КБ:
остальные объявлены в `@font-face` и подтягиваются только при реальном
использовании. Курсивные — при первом курсиве на странице, Inter — не
подтягивается вовсе (единственное место, где он есть, — витрина токенов
`/_design/`, а она закрыта `DEBUG`). Резерв тут в поднаборах: 480 КБ это
полное покрытие Unicode, а порталу нужны кириллица и латиница.

**Media** — загруженные файлы; через git не переезжает, требует бэкапа, в
проде раздаётся веб-сервером (отдавать её через Django нельзя — это
блокирующий воркер на каждой картинке). Проверить это явно в день
деплоя: whitenoise раздаёт `/static/`, но **не** `/media/`.

## По расписанию

Раз в минуту:

```bash
uv run python manage.py push_notifications
```

Отправляет неотправленные уведомления в Telegram — тем же ботом, которым
человек вошёл: право писать виджет входа запрашивает сразу
(`request-access=write`). В запросе пользователя этого не делают — Telegram,
отвечающий три секунды, означал бы форму комментария, отвечающую три
секунды. Событие пишется в базу сразу и видно на сайте, команда только
догоняет его сообщением.

Два прохода одновременно невозможны: команда берёт консультативную
блокировку Postgres и, не получив её, молча уходит до следующей минуты.
Это не перестраховка — двести сообщений при десятисекундном таймауте
укладываются в полчаса, а отметка «отправлено» ставится после ответа
Telegram и пачкой в конце: без блокировки второй запуск слал бы те же
строки второй раз. `flock` в cron делал бы то же, но снаружи и молча —
забытый при переносе на другой сервер, он ничем о себе не напомнит.

Пустой `TELEGRAM_BOT_TOKEN` — рассылка пропускается с предупреждением в
stderr; в разработке это норма. Событие старше часа не отправляется вовсе:
«главу одобрили» через сутки приходит тому, кто давно всё увидел сам.
Закрытый бот снимает `User.telegram_push` — очередь не ломится в закрытую
дверь на каждом проходе.

Пять задач, раз в сутки:

```bash
uv run python manage.py snapshot_portal
uv run python manage.py recount_views
uv run python manage.py recount_engagement
uv run python manage.py prune_old_rows
uv run python manage.py clearsessions
```

`snapshot_portal` замораживает сводку `/moderation/summary/` за вчерашние
сутки. Она единственная здесь пишет то, чего иначе просто не будет:
накопленные счётчики **убывают** — аккаунт удаляется полностью, работа
сносится автором, — и «сколько нас было в среду» после среды не
восстанавливается ничем. Возвращаемость читателя тем более: она считается
по журналу прочтений, а тот живёт две недели.

Порядок с `recount_views` не важен — вчерашние строки журнала не бывают
старше окна. Важна регулярность: пропущенный день наверстывается
`--day ГГГГ-ММ-ДД`, но не глубже двух недель, дальше читателя уже не
посчитать. Команда идемпотентна, повтор за тот же день переписывает
строку.

`recount_views` пересчитывает окно «Қазір танымал» по журналу прочтений и
вычищает строки, вышедшие из него. Без неё колонка только растёт:
дефолтная сортировка каталога со временем сойдётся с «Ең көп оқылған», а
таблица журнала — с трафиком за всё время.

`recount_engagement` сверяет `Story.comments`/`likes`, `User.followers`,
`StoryComment.likes` и `PollOption.votes` с реальными строками — страховка
поверх сигналов в `core/counters.py`: те двигают счётчик на каждом создании
и удалении строки, включая массовое удаление в админке и каскад от удаления
пользователя, но не видят `bulk_create`/`bulk_update` и прямую правку в базе.

`prune_old_rows` убирает то, что копится молча. Уведомления: лента
показывает неделю, таблица хранила всё, а событий по шесть типов на
каждое действие портала. Ревизии глав: каждая отправка на модерацию —
полная копия тела главы, потолок которой миллион знаков, и десять
возвратов на доработку это десять копий. Не трогаются опубликованная
ревизия (её удаление сняло бы текст с публикации) и поданная, сколько бы
она ни ждала модератора.

`clearsessions` убирает истёкшие сессии. Она нужна не «на всякий
случай»: сессии лежат в базе, а страница произведения пишет в сессию
список уже прочитанного — тем самым заводит строку **каждому гостю**,
открывшему любую работу. Без уборки эта таблица растёт ровно с трафиком
и не убывает никогда, то есть со временем становится самой большой в
базе, и понять откуда — уже некому.

Все пять суточных идемпотентны, пропуск дня ничего не портит. У рассылки
идемпотентность своя, какая бывает у отправки: повторный запуск не шлёт
уже ушедшее, но падение посреди прохода может отправить одно сообщение
дважды — отметка ставится после ответа Telegram, и выбор тут между
«дважды показали» и «молча потеряли».

## Бэкап и восстановление

Содержимое — единственный актив платформы, и рядом с ним живёт удаление
аккаунта: немедленное, полное, каскадом, без периода хранения. Поэтому
резервная копия не «хорошая практика», а условие запуска.

```bash
BACKUP_DIR=/backups ops/backup.sh
```

Раз в сутки, из cron. Снимает дамп базы (`--format=custom`) и архив
`media/` в один каталог с манифестом; хранит семь суточных, четыре
недельных и шесть месячных копий, недельные и месячные — жёсткими
ссылками, то есть без удвоения места. `BACKUP_DIR` обязан быть **на
другом носителе**: копия рядом с оригиналом спасает от кривой миграции и
не спасает от умершего диска, а умирают чаще диски.

```bash
BACKUP_DIR=/backups ops/restore.sh /backups/daily/2026-09-19
```

Перезаписывает базу и `media/`, поэтому спрашивает подтверждение:
единственный способ потерять данные при восстановлении — восстановить не
туда. Зашифрованный снимок понимает сам: расшифровывает во временный
каталог и стирает его при выходе.

**Сторож важнее шифрования.** Молча переставший отрабатывать cron — самый
частый способ остаться без бэкапа: скрипт писал в stderr, stderr читает
cron, cron пишет письмо, письма никто не настраивал. Отчёт уходит в
Telegram тем же ботом, что и уведомления, — и на удачный проход тоже:
молчание становится сигналом только тогда, когда сообщение приходит
каждый день.

```bash
TELEGRAM_BOT_TOKEN=… BACKUP_CHAT_ID=… BACKUP_DIR=/backups ops/backup.sh
```

Две необязательные переменные включаются, когда есть куда. Обе — про то,
чтобы копия пережила саму машину: «другой носитель» на одном сервере не
спасает от потерянного сервера.

| Переменная | Что делает |
|---|---|
| `BACKUP_GPG_RECIPIENT` | шифрует дамп и архив на этот ключ, открытые файлы удаляет |
| `BACKUP_REMOTE` | `rsync` суточной полки наружу: второй диск, другая машина, хранилище |

Порядок именно такой: незашифрованная копия, которая есть, лучше
зашифрованной, которой нет. Поэтому без ключа бэкап не останавливается, а
просто не шифрует.

**Пункт чек-листа закрывается не скриптом, а проверкой.** Один раз, до
запуска: поднять пустую базу, восстановить вчерашний снимок, открыть
главную и страницу произведения с обложкой. Бэкап, который никто не
восстанавливал, — копия неизвестного качества. Дату проверки записать
сюда:

| Когда проверяли восстановление | Кто | Результат |
|---|---|---|
| — | — | ⛔ ещё не проверяли |
